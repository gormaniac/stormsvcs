## (a) PR #17: the snort service (slib.snort)

### Takeaway
PR #17 adds `svcs/snort` (`snortsvc`, Storm pkg `slib.snort` v0.1.0): a **Snort 3** (3.12.4.0, built from source) service that treats enabled `it:app:snort:rule` nodes in the Cortex as the rule corpus, syncs Snort 3 Community + ET Open feeds into the Cortex as `it:app:snort:rule` in `meta:ruleset`s, scans `file:bytes` PCAPs (streamed from Storm or read directly from an Axon), parses `alert_json`, and models one `it:app:snort:hit` per (rule, flow) plus an `inet:flow` keyed differently from slib.pcap's flows. Suricata is an explicit README TODO (`it:app:suricata:rule`).

## (b) PR #16: the pcap service (slib.pcap)

### Takeaway
`svcs/pcap` (`pcapsvc`, pkg `slib.pcap` v0.1.0) downloads a capture from a configured Axon (`axon:url`, required), builds bidirectional flows in pure Python (dpkt) and optionally enriches them with tshark (`-T ek`, matched by frame number), extracts files to the Axon, and yields a summary followed by flow dicts that Storm models as fully populated `inet:flow` nodes keyed by an md5 of (capture sha256, ipproto, 5-tuple, start ns).

### Cited Findings
- Two passes: (1) dpkt flow pass always; (2) tshark when installed for TLS certs, SSH host keys, RDP client details, softnames/CPEs, and files (to the Axon); TLS 1.2/1.3 decryption with NSS key logs from the Axon; "tshark's output is matched to flows by frame number, so flows are always built the same way whether or not tshark ran" — [PR16 README](https://github.com/gormaniac/stormsvcs/blob/claude/pcap-flow-analyzer/svcs/pcap/README.md)
- Formats: libpcap (usec/nsec, both endians), pcapng (per-interface linktype/resolution/offset, multi-section), gzip of either; link types Ethernet (VLAN/QinQ/PPPoE), raw IP, NULL/LOOP, SLL/SLL2, PPP; TCP/UDP keyed by addr+port, other IP protos by addr — same README
